# 飞书 IT 工单使用教程

本教程对应仓库中的 `1.1.13` 代码，面向报修人、IT 处理人员和日常管理员。界面入口由所在组织配置；如果找不到报修表单或 IT 群，请联系管理员提供当前 V2 入口。工单的**最终状态以飞书多维表格记录为准**，卡片可能稍后同步。

## 报修人：提交与确认

1. 用自己的飞书账号打开 V2 报修表单，填写故障类型、故障设备、故障现象；有助于排查的截图或文件可放在报修附件中。联系电话和优先级按表单要求填写。
2. 提交后等待系统生成工单号和 IT 群卡片。系统要求“报修人”与实际提交人一致，不支持代他人提交。
3. IT 提交处理结果后，原报修人会收到私聊确认卡片。先核实故障，再点 **故障已恢复** 或 **故障未恢复**。只有原报修人能做这一步。
4. 点“故障未恢复”会让工单回到“处理中”，IT 继续处理；点“故障已恢复”会关闭工单。提交处理结果后满 **6 个自然小时**仍未反馈，系统会标记为“超时自动关闭”，保留 IT 原处理结果；这不等于用户主动确认。

如果没有收到私聊卡片，先查看表格中的工单状态是否为“待用户确认”，再联系管理员检查同步任务和机器人消息可达性。不要反复提交同一张报修表单。

## IT 处理人员：在群卡片操作

1. 新工单显示为“待处理”。在群卡片可填写接单说明，并点 **接单**。预计完成时间是选填项；留空时按实际接单时间顺延 **30 个自然分钟**，手动填写时必须是未来时间。
2. 如果不属于 IT 服务范围或是重复工单，填写**拒绝原因**后点 **拒绝并关闭**。拒绝原因会保存为处理结果。
3. 接单后状态变为“处理中”。当前处理人可用 **更新进展** 记录已完成事项与下一步；需要延期时选择晚于当前预计完成时间的新时间，再点 **延期**。
4. 处理完成后填写明确的处理结果，点 **提交处理结果**。状态变为“待用户确认”；后续由原报修人在私聊卡片反馈，或在 6 小时无反馈后由定时任务自动关闭。

只有 IT 名单中的人员或管理员可以接单。接单后，通常只有当前处理人或管理员能更新进展、延期和提交结果。选择日期时间后还需点击对应按钮，单独选择日期不会提交操作。

## 状态与常见问题

| 表格状态 | 含义 | 下一步 |
| --- | --- | --- |
| 待处理 | 已生成工单，等待 IT 接单或拒绝 | IT 在群卡片操作 |
| 处理中 | IT 已接单，或报修人反馈故障未恢复 | 当前处理人继续处理 |
| 待用户确认 | IT 已提交处理结果 | 原报修人确认恢复情况 |
| 已关闭 | 用户确认、IT 拒绝，或超时自动关闭 | 查看“关闭类型”和处理结果 |

- **点击旧卡片没推进状态**：系统会按最新记录刷新卡片。请在新卡片上继续，不要重复点击旧卡片。
- **卡片提示“暂未确认”**：先看多维表格的状态和流程版本。表格已变化就等待卡片同步；表格未变化再使用最新卡片重试一次。
- **表格已变化、卡片仍旧**：请管理员检查 `/jobs/sync` 的执行结果；不要手工修改卡片消息 ID。
- **SLA 与 6 小时确认期限不同**：SLA 按工作时段计算；用户确认期限从“处理完成时间”起按自然时间计算。

管理员排查时，先看多维表格真实状态，再按工单号、记录 ID 和操作时间查云函数日志，最后检查卡片及自动化。`/health` 可检查服务版本与配置是否齐全，但不能代替一次真实工单的端到端验收。部署参数见[字段与部署](字段与部署.md)，故障步骤见[运维与故障排查](运维与故障排查.md)。请勿把真实凭据、OpenID、工单日志或含个人信息的截图提交到 GitHub。

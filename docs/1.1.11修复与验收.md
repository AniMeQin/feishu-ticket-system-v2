# 1.1.11 修复与验收

基准：2026-09-21 从腾讯云 `feishu-ticket-api-v2` 下载的线上 1.1.10 代码包。
原包 SHA-256：`996d6162e9e8749f758c3f1c8068eb8c0d661d83634cb0bb16f6a2a9d083a626`。
原包保留于项目 `backups/2026-09-21-online-v1.1.10/feishu-ticket-api-v2.zip`。

## 已确认的现象与代码缺陷

- 9 月 21 日日志发现 12 条 ACTION_TIMEOUT；截图工单之后实际已关闭、流程版本为 4，证明至少部分超时不能当作操作失败。
- 首次读取工单固定上限 1300ms；尚未写入和写入结果未知使用相同错误提示。
- 卡片 JSON 全部缺少 `config.update_multi: true`。飞书 PATCH 接口要求更新前后的卡片都显式开启共享更新。
- 15 条同步 HTTP 400 日志未保留飞书业务错误码和请求标识；无法追溯这些历史错误各自的准确原因。
- 永久性 400 也重试三次；群卡片失败会中断报修人卡片刷新，通知发送失败也会跳过群卡片刷新。
- 14 条签名回退告警尚未区分请求头缺失、时钟偏差和摘要不一致，不能据此判定为攻击或错误密钥。

## 本次变更

1. 回调总预算从收到请求开始计算，最多 2850ms。首次读取可使用约 1950ms，保留写入时间；写入使用剩余预算。未提交明确提示可重试；写入结果未知用警告提示，不宣称失败或后台已经完成。
2. 保留写后读取确认，不自动重发状态写入。当前实例短期保留未确认写入，60 秒内重复点击先读取状态，未观察到版本推进则阻止重写。确认后旧版本卡片只刷新状态。
3. 重复事件重放已完成的卡片响应；处理中的事件给等待提示，去重记录有有效期。
4. 所有新发卡片和回调卡片显式开启共享更新。同步遇到明确的 230031（超过 14 天），或 230001/230099 且读取原消息确认是非共享卡片时，为未关闭工单补发替换卡片并保存新 ID。相同原消息使用相同 UUID，降低保存 ID 失败时的重复发送风险。
5. 不因未知 400、权限错误、删除或撤回消息而盲目补发；已关闭历史工单不补发。无法确认旧卡片配置时保留报错供现场处理。
6. 保留 HTTP 状态、业务错误码、简化错误说明和 Log ID，去掉 ErrorValue 后的内容、已知密钥与 Bearer 值。不记录完整响应体或请求凭据。只对限流、服务端错误或网络错误执行原有有限重试。
7. 群卡片和报修人卡片独立同步，单侧失败不再阻断另一侧。待确认卡片不再提前声称“已私聊报修人”。
8. 签名回退增加原因分类，不记录签名、Nonce、密文或 Token。维持原有解密和 Verification Token 校验，未盲目启用严格签名拒绝。
9. 修正包内不存在 scheduler 时仍检查 scheduler 的脚本；本次不修改线上独立 SLA 调度函数。

## 验证与边界

本地回归覆盖接单→完成→报修人确认关闭、延期和返工、权限限制、1.4 秒慢读取、写入确认丢失、重复事件、并发点击、未确认写入、400 分类、旧卡片替换和两侧通知隔离。所有外部服务均为模拟，没有操作真实工单或发送消息。

运行 `npm test` 和 `npm run check`。Node.js 需要 18 或以上；线上运行环境为 Node.js 20.19。默认时间仍由用户选择，未实施“两小时以后”等功能优化。

这不是消除所有网络超时的保证。飞书三秒回调限制仍然存在；若线上读写总耗时超过预算，应使用持久化队列方案另行设计，不能依赖 Web 云函数响应后的内存任务。当前锁、事件去重和未确认写入保护仅限单实例，不是分布式锁。

15 条历史 400 的具体业务错误码无法从旧日志恢复。`update_multi` 缺失是已确认的不兼容，但不能声称它解释了所有 400。签名告警和 499 的根因仍待线上新日志验证。

## 线上发布与回退

- 尚未发布，需按用户给定项目规则在生产最终动作前确认。
- 范围仅为上海/default 下主函数 `feishu-ticket-api-v2` 的代码；保留现有环境变量、监听 9000、启动脚本和独立 SLA 调度函数。
- 发布后健康检查应报告 `1.1.11-lite`。健康检查通过只代表服务可用，不代表工单业务验收完成。
- 授权测试工单需验证接单、完成、用户确认、双方卡片及多维表格版本一致，并检查 `WRITE_UNCONFIRMED`、`sync_failed`、`callback_auth` 分类日志。
- 正常同步可能为符合修复条件的未关闭工单补发卡片。旧消息保留；已关闭或未知错误不批量重发。
- 出现回归时，将备份 1.1.10 原包部署回同一主函数；本次无表结构变更。代码回退不会撤销已完成工单动作或已补发消息，需要按实际状态处理，不能回滚工单字段覆盖新数据。

# 版本变更与已修复问题

本文记录 Lite V2 从最初可运行版本到当前 `1.1.10-lite` 的关键修复。重点是说明为什么修改，以及旧问题现在由哪一层防护。

## 1. 当前版本结论

`1.1.10-lite` 在 `1.1.9-lite` 已验收链路上优化了终端用户确认卡片的发送时序：

```text
表单提交
  -> 待处理
  -> 接单
  -> 更新进展
  -> 延期
  -> 提交处理结果
  -> 待用户确认
  -> 用户确认恢复
  -> 已关闭
```

验收需同时核对多维表格、IT 群卡片、报修人私聊卡片和腾讯云日志。自动化测试共 66 项。

## 2. 主要逻辑漏洞及修复

| 旧问题 | 风险 | 当前处理 |
| --- | --- | --- |
| 500ms 后提前返回“后台处理中” | 云函数响应结束后后台 Promise 被中断，形成假成功 | 删除提前成功和关键后台任务；写入必须在当前回调中执行并确认 |
| 写入响应超时但实际已经落库 | 用户看到错误后重复点击，造成冲突 | 写入未明确时立即回读；已落库按成功处理，未确认只给准确提示 |
| 旧卡片仍可提交 | 重复接单、版本冲突或覆盖新状态 | 版本不一致时不写表，直接返回表格最新卡片 |
| 日期选择器被当成延期提交 | 用户只选日期就推进流程 | 非按钮回调统一忽略，只有明确按钮执行业务操作 |
| 群卡片、私聊卡片和表格不同步 | 用户与 IT 看到不同状态 | `/jobs/sync` 统一按表格状态刷新活动卡片和最近关闭卡片 |
| 用户确认关闭后旧卡片仍显示待确认 | 关闭状态不完整 | 同步任务同时刷新群卡片和报修人关闭卡片 |
| 卡片回调 Token 校验位置不正确 | 合法回调被拒绝或错误报 `200671` | 先解密，再校验 Verification Token；解密和 Token 失败才返回 401 |
| 飞书本地化日期格式不兼容 | 接单或延期提示时间格式错误 | 兼容秒、毫秒、ISO、中文年月日和多种 picker 字段 |
| 卡片回调使用长重试 | 超过飞书三秒和 SCF 15 秒限制 | 卡片主写入不做分钟级重试；定时任务只重试 `250ms、750ms` |
| 跨消息更新依赖响应后的后台执行 | 腾讯云未启用异步时更新丢失 | 当前卡片同步返回，其他通知和卡片由 `/jobs/sync` 补偿 |
| 缺少分钟级 SLA 调度 | SLA 逻辑存在但不稳定运行 | 新增独立事件函数，每 5 分钟调用 `/jobs/sla` |
| 错误日志只有最终失败 | 无法判断读取、写入还是回读失败 | 增加分阶段结构化日志和定时任务汇总 |

## 3. 版本记录

| 版本 | 主要变化 |
| --- | --- |
| `1.1.0-lite` | 建立 Lite V2 四状态流程、现有字段映射、群卡片和用户确认卡片；随后修复卡片 Token 分支和本地化时间输入 |
| `1.1.1-lite` | 加密回调统一先解密并校验 Verification Token；签名异常记录告警，避免代理层原始请求体差异误拒绝合法请求 |
| `1.1.2-lite` | 删除 500ms 假成功和关键后台 Promise；主状态写入改为同步完成、校验并返回真实卡片 |
| `1.1.3-lite` | 调整飞书三秒窗口内的读取、写入和回读期限，避免无限等待 |
| `1.1.4-lite` | 写入响应未返回时并行回读，识别“响应超时但实际已经落库”；补偿最近关闭群卡片和报修人卡片 |
| `1.1.5-lite` | 定时任务重试固定为秒级；增加 `scheduled_job received/completed/failed` 汇总日志 |
| `1.1.6-lite` | 按即时同步与每日三次兜底扫描调整关闭卡片补偿窗口和同步行为 |
| `1.1.9-lite` | 旧卡片自动刷新、日期选择器回调隔离、通信预算调整为 2850ms、用户提示改为实际状态语义、增加独立 SLA 调度器和完整文档 |
| `1.1.10-lite` | 即时同步支持按 `record_id` 只处理当前工单；待用户确认卡片优先于群卡片和历史关闭卡片刷新发送 |

`1.1.7` 和 `1.1.8` 是生产修复过程中的中间部署编号，没有形成独立 Git 提交；最终统一收口到 `1.1.9-lite`。

## 4. 1.1.10 与上一轮部署的直接差异

1. **即时同步从全表改为定向。** 自动化传入当前记录 ID 后，只读取和同步本次变化的工单。
2. **终端用户通知优先。** 待用户确认卡片先于群卡片和历史关闭卡片刷新发送。
3. **旧自动化仍可兼容。** 未传记录 ID 时仍执行全量扫描，但会先完成所有待确认用户通知。
4. **每日兜底能力不变。** 三次定时任务继续以无记录 ID 的方式执行全量补偿。

## 5. 未改变的业务决策

- 不新增多维表格字段。
- 不新增审批或延期审批。
- 延期直接修改现有预计完成时间。
- 不关联被取消的工单；需要时重新提交新工单。
- 接单预计完成时间必填，不设置延期次数上限。
- 周一至周五 `08:00-17:00` 计入 SLA，午休 `12:00-13:00` 暂停，周末和法定节假日不计。
- 旧代码和最初多维表格不作为回退目标，后续只在 Lite V2 主线上修复向前。

## 6. 仍需遵守的技术边界

- 飞书约三秒回调上限仍然存在；系统解决的是假成功和错误语义，不可能取消平台协议限制。
- 系统以最终一致为目标，不承诺跨多维表格和消息系统的强事务一致。
- 生产最大并发必须保持 `1`；当前代码没有跨实例分布式锁。
- `/jobs/sync` 是一致性保障的一部分，不是可选的监控接口。
- 每年必须维护新的节假日数据，否则下一年度 SLA 会只排除周末而无法排除新增法定假日。

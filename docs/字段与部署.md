# 字段、配置与部署

本文是 `1.1.10-lite` 的生产部署基线。后端不会创建或重命名字段；字段名、类型、飞书权限和云函数参数必须在部署前人工核对。

## 1. 多维表格字段

### 1.1 用户与表单字段

| 字段 | 建议类型 | 用途 |
| --- | --- | --- |
| 报修人 | 人员 | 必须与系统“提交人”一致；初始化时统一写入实际提交人 |
| 提交人 | 系统人员字段 | 禁止代报修的身份依据 |
| 提交时间 | 系统日期时间字段 | 报修时间缺失时的创建时间来源 |
| 联系电话 | 文本 | 优先使用表单值；为空时尝试读取用户资料手机号 |
| 故障类型 | 单选 | 报修分类 |
| 故障设备 | 文本 | 报修对象 |
| 故障现象 | 多行文本 | 问题描述 |
| 报修附件 | 附件 | 可选附件 |
| 优先级 | 单选 | P1、P2、P3、P4；为空时使用 `DEFAULT_PRIORITY` |

### 1.2 系统流程字段

| 字段 | 建议类型 | 写入时机 |
| --- | --- | --- |
| 工单号 | 文本 | 初始化；格式 `IT-YYYYMMDD-记录ID后六位` |
| 工单状态 | 单选 | 初始化和每次状态变化 |
| 流程版本 | 数字或文本 | 初始化及每次业务操作；旧卡片校验依据 |
| 报修人 OpenID | 文本 | 初始化或身份修复 |
| 报修时间 | 日期时间 | 初始化，Unix 毫秒时间戳 |
| SLA 截止时间 | 日期时间 | 初始化，根据工作时间计算 |
| 是否曾经超时 | 单选 | 初始化为否；首次超时后永久为是 |
| SLA 首次提醒时间 | 日期时间 | 首次 SLA 提醒发送成功后 |
| 处理人 | 人员 | 接单 |
| 处理人 OpenID | 文本 | 接单；后续操作权限依据 |
| 接单时间 | 日期时间 | 接单 |
| 预计完成时间 | 日期时间 | 接单和延期 |
| 当前进展 | 多行文本 | 接单、更新进展或用户反馈未恢复 |
| 处理结果 | 多行文本 | 提交处理结果或拒绝关闭 |
| 关闭时间 | 日期时间 | 用户确认恢复或 IT 拒绝关闭 |
| 返工次数 | 数字或文本 | 初始化为 0；用户反馈未恢复时加一 |
| 当前群卡片 ID | 文本 | 群卡片发送成功后 |
| 当前用户卡片 ID | 文本 | 私聊确认或拒绝通知发送成功后 |

业务时间字段统一使用飞书“日期时间”类型，后端写入 Unix 毫秒时间戳。

无需新增以下字段：希望处理时间、原始 SLA 截止时间、IT 提交完成时间、用户确认时间、关闭类型、延期次数、延期审批人、审批状态、审批时间或独立补偿任务字段。

## 2. 可选事件日志表

系统始终向腾讯云函数日志写入结构化事件。默认不新建事件日志表。

如果已经存在历史事件表，可配置 `FEISHU_EVENT_TABLE_ID`，字段应为：

- 工单号
- 工单记录 ID
- 操作类型
- 操作人 OpenID
- 操作人名称
- 操作前状态
- 操作后状态
- 说明
- 操作时间

事件表只追加，不参与状态判断。未配置时不影响主流程。

## 3. 主函数环境变量

### 3.1 必填变量

| 变量 | 内容 | 安全要求 |
| --- | --- | --- |
| `FEISHU_APP_ID` | 飞书自建应用 App ID | 不写入仓库 |
| `FEISHU_APP_SECRET` | 飞书自建应用 App Secret | Secret，轮换后重新部署 |
| `FEISHU_VERIFICATION_TOKEN` | 飞书事件订阅 Verification Token | 必须与飞书开放平台完全一致 |
| `FEISHU_ENCRYPT_KEY` | 飞书事件订阅 Encrypt Key | 必填；缺失时服务拒绝启动 |
| `FEISHU_INTERNAL_JOB_TOKEN` | `/jobs/sync` 和 `/jobs/sla` 的 Bearer Token | 独立随机值，不复用 Verification Token |
| `FEISHU_BITABLE_APP_TOKEN` | 多维表格 app token | 只填写 token，不填写完整 URL |
| `FEISHU_TICKET_TABLE_ID` | 工单主表 table ID | 必须指向当前 V2 表 |
| `FEISHU_IT_CHAT_ID` | IT 群 chat ID | 应用必须已加入该群 |
| `FEISHU_IT_OPEN_IDS` | 可接单人员 OpenID，逗号分隔 | 不提供默认人员 |

### 3.2 推荐或可选变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `9000` | Web 函数监听端口 |
| `FEISHU_ADMIN_OPEN_IDS` | 空 | 管理员 OpenID；可代替处理人操作，不能代替报修人确认 |
| `FEISHU_EVENT_TABLE_ID` | 空 | 仅当已有事件日志表时填写 |
| `FEISHU_BITABLE_URL` | 空 | 卡片“查看工单详情”链接的基础 URL |
| `DEFAULT_PRIORITY` | `P3` | 表单优先级为空时使用 |
| `SLA_P1_HOURS` | `1` | P1 工作小时 |
| `SLA_P2_HOURS` | `2` | P2 工作小时 |
| `SLA_P3_HOURS` | `8` | P3 工作小时 |
| `SLA_P4_HOURS` | `40` | P4 工作小时 |
| `SLA_HOLIDAYS` | 空 | 追加节假日，逗号分隔 `YYYY-MM-DD` |
| `BITABLE_RECORD_SETTLE_INTERVAL_MS` | `500` | 新记录表单字段稳定检查间隔 |
| `CARD_CALLBACK_BUDGET_MS` | `2850` | 飞书三秒通信窗口内的内部预算；不要随意调大 |
| `APP_COMMIT` | `local-build` | 当前部署的 Git 短提交号，供 `/health` 核对 |

变量列表以根目录 `.env.example` 和 `src/config.js` 为准。不要把真实值写进 `.env.example`。

## 4. 飞书应用配置

### 4.1 应用能力

飞书自建应用至少需要以下能力：

- 读取、更新和列出指定多维表格记录；
- 以应用身份向群和用户发送消息；
- 更新应用发送的互动卡片；
- 根据 OpenID 读取用户基础信息；如需自动补手机号，还需相应通讯录权限；
- 接收记录新增事件和 `card.action.trigger` 卡片回调。

具体权限名称以飞书开放平台当前控制台为准。权限变更后必须发布新应用版本并由管理员审批生效。

### 4.2 事件订阅

- 回调地址：`<主函数 URL>/feishu/events`。
- 配置与环境变量一致的 Verification Token 和 Encrypt Key。
- 订阅工单新增相关事件及互动卡片回调。
- URL 验证必须返回 challenge；验证失败先检查 Encrypt Key 和 Verification Token。

### 4.3 多维表格自动化

建议配置两类自动化：

1. **流程版本变化即时同步**
   - 触发字段：仅“流程版本”。
   - 动作：向 `<主函数 URL>/jobs/sync` 发送 POST。
   - Header：`Authorization: Bearer <FEISHU_INTERNAL_JOB_TOKEN>`。
   - Header：`Content-Type: application/json`。
   - 请求体增加 `record_id`，值必须通过飞书变量选择器选取“触发记录 → 记录 ID”，不要手工填写固定记录 ID。
   - 不监听“当前群卡片 ID”或“当前用户卡片 ID”，避免循环触发。

2. **每日兜底同步**
   - 时间：`09:00、13:30、17:30`。
   - 调用方式与鉴权同上。
   - 请求体留空，不传 `record_id`，保持全量扫描。

即时同步只处理本次变化的工单并优先发送用户确认卡片；每日任务负责全量补偿遗漏自动化、发送失败和短暂网络故障。

## 5. 腾讯云主 Web 函数

| 配置项 | 生产值 |
| --- | --- |
| 函数类型 | Web 函数 |
| 运行环境 | Node.js 20.19 或同级 Node.js 20 |
| 时区 | `Asia/Shanghai` |
| 监听端口 | `9000` |
| 执行超时 | `15 秒` |
| 初始化超时 | `65 秒` |
| 内存 | `512MB` |
| 公网访问 | 启用 |
| 异步执行 | 关闭 |
| 请求多并发 | 自定义静态并发，最大值 `1` |
| 就绪检查 | 启用，路径 `/health` |

最大并发 `1` 是当前一致性设计的一部分。提高并发前必须先改造跨实例并发控制。

## 6. SLA 调度器

飞书多维表格自定义重复不适合分钟级 SLA，Web 函数也不能直接绑定定时触发器，因此使用独立事件函数 `feishu-ticket-sla-scheduler-v2`。

### 6.1 打包

```bash
npm run zip:scheduler
```

### 6.2 事件函数配置

| 配置项 | 生产值 |
| --- | --- |
| 函数类型 | 事件函数 |
| 运行环境 | Node.js 20 |
| 执行方法 | `index.main_handler` |
| 执行超时 | `20 秒` |
| 时区 | `Asia/Shanghai` |
| Cron | `0 */5 * * * * *` |

环境变量：

| 变量 | 说明 |
| --- | --- |
| `TARGET_URL` | 主 Web 函数 URL，不带末尾 `/` |
| `INTERNAL_JOB_TOKEN` | 与主函数 `FEISHU_INTERNAL_JOB_TOKEN` 相同 |
| `REQUEST_TIMEOUT_MS` | 可选，默认 `12000` |

调度器只调用 `POST /jobs/sla`，不配置 App ID、App Secret 或多维表格凭证。

## 7. 发布步骤

### 7.1 发布前

```bash
npm ci
npm test
npm run check
git diff --check
```

确认：

- 当前分支包含准备上线的唯一 V2 代码；
- 工作区没有 `.env`、真实 token、生产 OpenID 或临时日志；
- `package.json` 与 `src/server.js` 版本一致；
- `APP_COMMIT` 准备更新为本次 Git 短提交号；
- 2026 年之后的节假日已经通过 `SLA_HOLIDAYS` 维护。

### 7.2 构建主函数

```bash
npm run zip
```

压缩包根目录必须包含：

- `app.js`
- `package.json`
- `scf_bootstrap`
- `src/`
- `docs/`

将 `feishu-ticket-system-lite.zip` 上传到主函数，选择全量上传并部署 `$LATEST`。

### 7.3 部署后

1. 打开 `/health`，确认 `version`、`commit`、`ready: true`、`missing: []`。
2. 检查函数就绪状态正常。
3. 用飞书控制台重新执行 URL 验证。
4. 检查 SLA 调度器最近一次调用成功。
5. 用真实表单创建一张测试工单。
6. 在真实群卡片完成接单、更新进展、延期和提交结果。
7. 在报修人私聊卡片确认恢复。
8. 核对多维表格、群卡片、私聊卡片均为“已关闭”。
9. 核对日志存在 `card_action` 和 `scheduled_job completed`，同步结果 `failed=0`。

## 8. 生产验收清单

- [ ] 缺少 Encrypt Key 时服务拒绝启动。
- [ ] 错误 Verification Token 或无法解密的回调返回 401。
- [ ] 内部任务缺少 Bearer Token 返回 401。
- [ ] 非 IT 人员不能接单。
- [ ] 接单未填写预计完成时间时，按本次接单时间加 30 个自然分钟保存具体时间；卡片和表格显示一致。
- [ ] 手动填写预计完成时间时采用所选时间，格式错误或不晚于当前时间则拒绝操作。
- [ ] 非当前处理人不能更新、延期或完成；管理员除外。
- [ ] 延期时间必须晚于当前预计完成时间，且不触发审批。
- [ ] 报修人与提交人不一致时不创建工单。
- [ ] 只有原报修人能确认恢复或反馈未恢复。
- [ ] 旧卡片不写表，点击后刷新到最新状态。
- [ ] 选择日期时间本身不推进流程。
- [ ] 写入未确认时不显示假成功。
- [ ] `/jobs/sync` 能补发群卡片和报修人卡片。
- [ ] 最近 24 小时关闭卡片能被补偿刷新。
- [ ] SLA 调度器每 5 分钟运行一次。
- [ ] 超时提醒只发送一次，“是否曾经超时”不恢复。
- [ ] 记录超过单页数量时仍可分页扫描。

## 9. 发布与回退原则

- 生产只运行当前 Lite V2，不保留最初旧代码的并行入口。
- 正常问题采用修复向前：修改、测试、发布新版本。
- GitHub 可保留提交和版本标签用于审计；紧急情况下只能重新部署已验收的 V2 构建物，不恢复已经废弃的最初版本和旧多维表格。
- 任何部署都必须重新完成真实卡片冒烟测试，不能只以“上传成功”作为上线完成依据。
